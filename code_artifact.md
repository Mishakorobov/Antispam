# Техническая документация: Система блокировки колл-центров по пулам операторов

## 1. Общая концепция и архитектура

Система построена по гибридной модели **Offline-First клиент + аналитический бэкенд**. Вся проверка входящего вызова выполняется локально на устройстве за $5\text{–}15\text{ мс}$ без сетевых запросов в момент звонка. Облако используется исключительно для агрегации жалоб, анализа операторских диапазонов и фоновой рассылки обновлений.

### Клиентская часть (Android)
* **`CallScreeningService` (Kotlin):** Системный сервис (Android 10+), перехватывающий вызов на уровне ОС до включения экрана и подачи звукового сигнала.
* **Локальная БД (SQLite / Room):** Хранит таблицу активных заблокированных диапазонов (`range_start`, `range_end`), локальный «белый список» и очередь неотправленных репортов.
* **Модуль обратной связи (Post-Call UX):** После завершения короткого звонка (например, длительностью менее 30 секунд) с незнакомого номера пользователю показывается уведомление с кнопкой быстрого репорта («Опрос / ВЦИОМ»).
* **`WorkManager` (Фоновая синхронизация):** Раз в $6\text{–}12$ часов скачивает дельту новых заблокированных пулов (несколько килобайт) и отправляет накопленные жалобы на сервер.

### Серверная часть (Бэкенд)
* **Парсер реестра Минцифры (Cron-воркер):** Раз в неделю загружает актуальные CSV-выгрузки российской системы нумерации (`ABC-3xx`, `ABC-4xx`, `ABC-8xx`, `DEF-9xx`) с портала открытых данных и обновляет справочник операторских диапазонов.
* **API-шлюз (REST):** Два основных эндпоинта:
  * `POST /api/v1/report` — прием жалоб от пользователей.
  * `GET /api/v1/pools?since={version}` — раздача инкрементальных обновлений базы.
* **Движок кластеризации:** Анализирует плотность жалоб внутри операторских диапазонов и автоматически формирует правила блокировки микро-пулов.

## 2. Алгоритм определения и блокировки пулов

Колл-центры используют SIP-телефонию с динамической подменой номера из арендованных у операторов блоков. Чтобы не заблокировать обычных абонентов, применяется **двухуровневая кластеризация**:

1. **Нормализация номера:**
   Любой входящий российский номер приводится к 11-значному целому числу типа `Long` (например, `+7 (495) 123-45-67` $\rightarrow$ `74951234567`).
2. **Сопоставление с реестром Минцифры:**
   Сервер определяет оператора и емкость официального пула, которому принадлежит номер:
   * **Малые пулы и B2B/SIP-операторы (емкость до $1\,000$ номеров):** Если пул принадлежит оператору виртуальной АТС (МТТ, Манго Телеком, Телфин и др.), для блокировки всего официального диапазона `[official_start, official_end]` достаточно $3\text{–}5$ подтвержденных жалоб с разных устройств.
   * **Крупные пулы федеральных операторов (емкость от $10\,000$ номеров):** Сервер принудительно дробит их на виртуальные **микро-пулы по $100$ номеров** (`7XXXXXXXX00` – `7XXXXXXXX99`) и **подпулы по $1\,000$ номеров** (`7XXXXXXX000` – `7XXXXXXX999`).
3. **Правило срабатывания (Порог блокировки):**
   * При поступлении $\ge 3$ жалоб на **разные** номера внутри одной «сотни» от **уникальных** пользователей (`device_hash`) за 7 дней, весь диапазон `[X00, X99]` переводится в статус `BLOCKED`.
   * Если внутри одной «тысячи» заблокированы $\ge 3$ «сотни», блокировка автоматически расширяется на всю тысячу (`[X000, X999]`).
4. **Защита от ложных срабатываний и отравления базы (Anti-Poisoning):**
   * **Лимит голосов:** Одно устройство (`device_hash`) может отдать только 1 зачетный голос за конкретную «сотню» в течение 24 часов.
   * **Серверный Whitelist:** Официальные диапазоны банков, экстренных служб, курьерских и государственных сервисов исключаются из автоматической блокировки.
   * **Время жизни правила (TTL):** Аренда пулов колл-центрами носит временный характер. Блокировка микро-пула выдается на 30 дней. По истечении срока пул переводится в режим наблюдения (разблокируется), и при поступлении $\ge 2$ новых жалоб блокируется повторно на 60 дней.

## 3. Структура баз данных

### Клиентская БД (SQLite / Android)

```sql
CREATE TABLE blocked_pools (
    range_start INTEGER NOT NULL, -- Начало диапазона (например, 74951234500)
    range_end   INTEGER NOT NULL, -- Конец диапазона (например, 74951234599)
    operator    TEXT,             -- Название оператора из реестра
    category    TEXT,             -- Категория ('SURVEY', 'SPAM')
    updated_at  INTEGER,          -- Timestamp последнего обновления
    PRIMARY KEY (range_start, range_end)
);

CREATE INDEX idx_pools_lookup ON blocked_pools (range_start, range_end);

CREATE TABLE local_whitelist (
    phone_number INTEGER PRIMARY KEY,
    added_at     INTEGER
);
```

### Серверная БД (PostgreSQL / Cloudflare D1)

* **`registry_ranges`** (Справочник Минцифры):
  * `id` (BIGSERIAL PK)
  * `code_abc_def` (INT) — код зоны (495, 903 и т.д.)
  * `range_start` (BIGINT)
  * `range_end` (BIGINT)
  * `capacity` (INT)
  * `operator_name` (TEXT)
  * `region` (TEXT)
* **`user_reports`** (Сырые жалобы):
  * `id` (BIGSERIAL PK)
  * `phone_number` (BIGINT)
  * `bucket_100` (BIGINT) — вычисляемый идентификатор сотни (`phone_number / 100`)
  * `device_hash` (TEXT) — анонимизированный хэш устройства
  * `created_at` (TIMESTAMP)
* **`active_blocks`** (Таблица для раздачи клиентам):
  * `range_start` (BIGINT)
  * `range_end` (BIGINT)
  * `confidence_score` (INT)
  * `expires_at` (TIMESTAMP)
  * `version` (BIGINT) — инкрементальный номер версии для синхронизации дельт

## 4. Логика перехвата вызова на Android

При поступлении входящего звонка система вызывает метод `onScreenCall` внутри наследника `CallScreeningService`:

1. Извлечь номер звонящего из `callDetails.handle.schemeSpecificPart`.
2. Проверить наличие номера в телефонной книге пользователя через `ContactsContract.PhoneLookup` (и локальный `local_whitelist`). **Если контакт найден — немедленно разрешить вызов.**
3. Очистить номер от лишних символов и привести к формату `Long` (`7XXXXXXXXXX`).
4. Выполнить быстрый поиск по индексу в локальной SQLite:
   ```sql
   SELECT 1 FROM blocked_pools 
   WHERE :normalizedNumber BETWEEN range_start AND range_end 
   LIMIT 1;
   ```
5. Если совпадение найдено, отклонить вызов на уровне телеком-стека:

```kotlin
override fun onScreenCall(callDetails: Call.Details) {
    val rawNumber = callDetails.handle?.schemeSpecificPart ?: return
    val normalizedNumber = normalizePhoneNumber(rawNumber)

    if (isContactOrWhitelisted(normalizedNumber)) {
        allowCall(callDetails)
        return
    }

    if (databaseHelper.isNumberInBlockedPool(normalizedNumber)) {
        val response = CallResponse.Builder()
            .setDisallowCall(true)      // Запретить вызов
            .setRejectCall(true)        // Отклонить (сбросить)
            .setSkipCallLog(false)      // Оставить запись в журнале звонков
            .setSkipNotification(true)  // Не показывать уведомление о пропущенном
            .build()
        respondToCall(callDetails, response)
    } else {
        allowCall(callDetails)
    }
}
```
